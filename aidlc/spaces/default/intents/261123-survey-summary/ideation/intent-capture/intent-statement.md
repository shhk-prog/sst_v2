# 意図ステートメント：大規模調査のまとめ

## Problem Statement

- 依頼は「大規模調査のまとめ」である。 [desc]
- まとめる対象は、FLMSEC 論文に使った v3 の大規模調査である。論文は v3/論文/FLMSEC にあり、論文に使った結果はすべて v3/results/vllm にある。 [Q1]
- この調査は、様々な merge 手法で secure merge を試し、セキュリティ 1 タスクと特化性能 3 タスクで性能を測ったものである。 [Q1]
- 既に提案した merge 手法（SST-Merge）は、この大規模調査で他の merge 手法との差を出せなかった。 [Q6]
- 解決したい課題は、この調査結果から secure merge に適した要素を抜き出し、それをもとに secure merge に適した新しい merge 手法の設計案を出すことである。新しい実験は行わないため、既存の結果から言えるのは、新手法が既存手法より優れている「可能性」までである。 [Q2] [Q4] [Q5] [Q6]

## Target Customer

- このまとめは、secure merge（提案論文 v3/論文/DLSP_hiromi2）に適した新しい merge 手法を提案するための材料として使う。 [Q2]
- 読み手は依頼者本人と指導教員である。 [Q8]
- 新手法を採用するかどうかは、共同研究者と合議で決める。 [Q9]
- 途中経過は定例ミーティングで報告する。 [Q10]

## Success Metrics

- 調査内容を確認し、結果から secure merge に適した要素を抜き出せていること。「適した要素」と判断する基準（セキュリティ 1 タスクと特化性能 3 タスクのどの指標で、どの手法同士を比べ、何を根拠に要素と呼ぶか）は、レポートの冒頭で定義し、その基準に沿って抽出結果を判定する。 [Q1] [Q4]
- 新しい merge 手法の設計案があり、既存手法に比べてどこがどう優れている可能性があるかを、理論と実験数値の両方で説明できること。 [Q6]
- レポートでは、既存の結果で裏付けられる主張と、新しい実験をしないと確かめられない仮説を分けて書くこと。 [Q5] [Q6]
- SST-Merge が大規模調査で他の merge 手法と差を出せなかった理由を、結果から理論と実験の両面で考察できていること。考察の根拠になる数値は、v3/results/vllm の結果ファイルまで辿れること。 [Q1] [Q6]
- 成果物は Markdown レポートと、v3/results/vllm から表を再生成するスクリプトで構成されていること。 [Q3]
- 本調査における実験数値・実験的考察は、v3/results/vllm に保存された既存の実験結果の集計・再分析に基づくものであり、新規の実験実行は含まない。 [Q1] [Q5]

## Initiative Trigger

- SST-Merge が大規模調査で他の merge 手法との差を出せなかったため、調査結果を見直して、secure merge により適した新しい merge 手法を提案したい。 [Q6] [Q2]
