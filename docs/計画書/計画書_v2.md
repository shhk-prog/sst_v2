# 1. 研究目的

本研究の目的は、**モデルマージ後に安全性、応答の非退化性、専門タスク性能を同時に維持できる条件を特定し、その成否を説明する重み空間上の設計要因を明らかにすること**である。

単にAttack Success Rate（ASR）が低いモデルを「安全」とみなすのではなく、

- harmful requestに対する安全性
- 正常な応答生成能力
- benign requestに対する過剰拒否
- domain-specific utility
- general capability

を分離して評価する。

さらに、単なる手法ランキングに留まらず、

1. どのマージ条件が成立するか
2. 成功・失敗を説明する重み特性は何か
3. その特徴が因果的に重要か
4. その知見を新しいSecure Merge設計に利用できるか

を段階的に検証する。

既存計画と同様、最初から特定の新手法が成功すると仮定せず、E2/E3の結果に応じてE4の設計を決定する。:chatgpt-content-reference{index="1"}

---

# 2. 中心Research Questions

| RQ | 問い | 対応Stage |
|---|---|---|
| **RQ1** | どのmerge手法・設定がSafety、Validity、Benign behavior、Utilityを同時に保てるか | E1 |
| **RQ2** | 成功するmergeと失敗するmergeでは、実際の重み更新にどのような違いがあるか | E2 |
| **RQ3** | 更新箇所・更新量・競合構造を直接操作すると、Safety / Validity / Utilityは因果的に変化するか | E3 |
| **RQ4** | E2/E3で確認された設計要因を利用して、既存手法より良いSecure Merge条件を構成できるか | E4/E5 |

# 3. 基本方針

```text
v3

        ↓
v4基準で再採点
        ↓
全手法Legacy Screening
        ↓

        ↓

        ↓

        ↓
```

重要な原則は、

> **既に生成済みのresponseは可能な限り再利用する。一方、旧集計値は原則として再計算する。**

である。

既存ログは探索・再集計には使用するが、新しい未見Testとは扱わない。Calibration / Development / Testの役割を分離し、既に結果を見たデータを後続新手法の独立評価に再利用しない。:chatgpt-content-reference{index="2"}

# 7. Safety / Validity指標

有害要求 \(i\) に対して、

- \(V_i\): 非退化出力なら1
- \(H_i\): 同一judgeで有害な要求達成と判定されたら1

とする。

\[
ASR_{\mathrm{all}}
=
\frac{\sum_i H_i}{N}
\]

\[
VRR
=
\frac{\sum_i V_i}{N}
\]

\[
ASR_{\mathrm{valid}}
=
\frac{\sum_i V_iH_i}{\sum_i V_i}
\]

\[
VSR
=
\frac{\sum_i V_i(1-H_i)}{N}
\]

とする。

\(\sum_iV_i=0\)なら`ASR_valid`は未定義とする。

invalid responseを自動的にsafeとはみなさない。

また、judge変更の影響とValidity filteringの影響を混同しないため、**ASR_allとASR_validは必ず同じjudge labelから計算する**。:chatgpt-content-reference{index="7"}

# 19. E2：成功・失敗を説明する重み特性

E1終了後、単に「上位と下位」を比較するのではなく、異なるfailure modeを選ぶ。

例えば、

```text
Balanced / FULL_FEASIBLE
Safety failure
Degeneration failure
Utility failure
```

から代表候補を選ぶ。

測定する重み特性は、

### 更新量

\[
r_g=
\frac{\|\theta_{m,g}-\theta_{u,g}\|}
{\|\theta_{u,g}\|+\epsilon}
\]

### 更新集中

- layer-wise update norm
- module-wise update allocation
- max concentration

### 選択性

- non-zero update ratio
- mask density
- modified parameter ratio

### Conflict

- safety vector / utility vector cosine
- sign conflict
- importance overlap

### 行動変化

- ΔASR
- ΔVRR
- ΔUtility
- ΔOver-refusal

とする。

E2は相関解析であり、原因とは断定しない。原因の検証はE3で行う。既存計画でもこの区別が明示されている。:chatgpt-content-reference{index="11"}

# 20. E3：因果介入

E2で見つけた候補特徴を直接操作する。

最低限、

| Condition | Location | Update amount |
|---|---|---|
| A | map-selected | common coefficient |
| B | random matched | common coefficient |
| C | map-selected | regional cap |
| D | random matched | regional cap |

を比較する。

さらに、

- original full merge
- uniform global shrink

- safety-only-selected region

を対照として入れる。

これにより、

> 良かったのは単に更新量が小さかっただけではないか

という代替説明を検証する。:chatgpt-content-reference{index="12"}
