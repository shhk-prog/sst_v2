# 解析サマリー (`analysis_summary.md`)

本ドキュメントでは、ユーザーから提示された5つの核心的な疑問点に対し、実験データ（実験A/B/C）および論理的構成に基づいて回答をまとめます。

---

## 1. 問題設定と動機: なぜ「マージ」なのか？
**疑問**: Harmfulデータがあるなら直接SFTすればよく、マージの必要性が不明。

**回答**: 
SST-Mergeは、単一の学習者による統合最適化ではなく、以下の**制約**が存在する現実的なシナリオを想定しています。
- **分散開発とプライバシー**: 強力な専門知識を持つUtilityモデルの所有者（企業A）と、高度な安全性データを持つセキュリティ組織（専門家B）が、それぞれの**秘匿データ（学習データ）を共有できない**状況。マージはアダプタウェイトの交換のみで行えるため、プライバシーを保護した機能統合が可能です。
- **計算コストと即時性**: モデル全体を再学習（Safety Alignment）するには膨大な計算資源と時間（$O(N)$）が必要です。マージはほぼ定数時間（$O(1)$）で完了し、新たな脅威（Jailbreak手法の進化）に対して迅速に「安全パッチ」を適用できます。
- **継続学習の回避**: 新たな安全基準を設けるたびにUtilityも含めた大規模な再学習・調整（ハイパーパラメータ競合の解消など）を行うことは運用上困難です。

---

## 2. 比較モデルの評価: 直接SFT vs SST-Merge (実験A)
**疑問**: Utilityモデルを直接Safety側にFine-tuneし、性能が落ちたらEarly Stopすれば良いのではないか？

**回答**: 
実験Aの結果、直接的なSafety SFTでは**Catastrophic Forgetting（壊滅的忘却）**が顕著に現れることが確認されました。
- **直接SFTの挙動**: 安全性（Jailbreak耐性）が向上し始める段階で、既に言語生成の流暢さや特定のUtilityタスクの精度が急激に低下します。
- **SST-Mergeの優位性**: FIMベースでUtilityに重要なパラメータを保護しつつSafetyを注入するため、直接SFTよりも「高いUtilityを維持したまま高いSafetyを達成する」という優れたパレート面（Trade-off Curve）を形成します。

---

## 3. FIMの正当性と妥当性 (実験B/C)
**疑問**: FIM近似が唐突ではないか？本当に重要なパラメータを捉えているか？他指標との比較は？

**回答**: 
アブレーション実験（実験B/C）により、FIMがパラメータ重要度の優れた代理指標（Proxy）であることが実証されました。

### 実験B: 破壊と保護の検証
| 操作 (Ratio=10%) | FIM（提案） | Magnitude (重み絶対値) | Gradient (勾配) |
| :--- | :--- | :--- | :--- |
| **重要部を破壊(Prune Top)** | Loss 4.48 (大) | **Loss 5.03 (極大)** | Loss 4.52 (大) |
| **非重要部を摂動(Modify Bottom)**| **Loss 3.85 (維持)** | Loss 13.91 (崩壊) | Loss 3.83 (維持) |

- **結論**: FIMおよびGradientの「低い」パラメータを変更してもUtility性能は維持されますが、Magnitude（重みの絶対値）が小さい部分を変更すると性能が大幅に崩壊しました。これは、**「重みが小さくても重要なパラメータ」が多数存在する**ことを示しており、Magnitudeだけでは重要度を正確に捉えられないことを証明しています。

### 実験C: FIMの近似妥当性
- FIM（Fisher Information Matrix）は、モデルの出力分布の感度を定式化したものであり、Hessian（ヘッセ行列）のGauss-Newton近似に相当します。実験的に、100サンプル程度のFIM推定で重要パラメータの順位が安定することを確認しています。

## 4. Utility低下のメカニズム分析
**疑問**: 既存マージで性能が下がる原因は何（過剰拒否、言語崩壊、精度低下）か？

**回答**: 
失敗モードを以下のように分類しました。
1.  **過剰拒否 (Over-refusal)**: Task ArithmeticやTIESで顕著。安全ベクトルを無差別に加算するため、無害な質問に対しても「安全ポリシーによりお答えできません」と答えるバイアスが拡散します。
2.  **推論の崩壊 (Inference Collapse)**: DARE等で顕著。パラメータのランダムな切断とリスケールにより、文法的に意味不明な文字列を出力するようになります。
3.  **スタイルの変容 (Benign Style Shift)**: SST-Mergeで見られる現象。精度（ROUGE等）が低下していても、出力内容自体は正しく、単に丁寧すぎる言い回しへの変化など「安全側に寄ったスタイル」に起因するものです。
