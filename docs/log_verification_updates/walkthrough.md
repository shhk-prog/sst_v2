## 修正内容のハイライト

1.  **ベースライン評価の信頼性（6.1節）**
    *   **修正箇所**: 6.1節冒頭のパラグラフ。
    *   **内容**: WizardMath単体のGSM8K（39.38%）やSafetyFT単体（7.19%）など、ベースモデルの性能がGitHubの生ログ（`results/debug_limit320/base/`）と完全に一致しており、ベースライン評価の信頼性が担保されていることを明記しました。

2.  **DELLA推論崩壊の条件混同（6.1節・6.2節）**
    *   **修正箇所**: 6.1節のTable 3の直下（注記）および、6.2節のパラグラフ。
    *   **内容**: 以前の版でTable 3に記載されていたDELLAの完全崩壊データ（Gibberish N=320）が、実は `safety+math` (2ドメイン) の結果ではなく `safety+math+code+medical` (4ドメイン) の結果が混入したものであったことを注記として明記。さらに6.2節において、極めて深刻な推論崩壊現象は、一般的な臨界点転移というよりも、4ドメインのような干渉負荷の大きい状況下特有の現象であることを明確に切り分けました。

3.  **GSM8K数値の不整合に関する留保（6.3節）**
    *   **修正箇所**: 6.3節の各手法AUCリストの直後。
    *   **内容**: 提案手法 (Diagonal SST) のGSM8Kの数値について、Table 3記載値と実際の生ログ（37.81%）、およびAppendix記載値との間に差異が見られることを指摘。このブレが集計スクリプトの版違いやシード平均の取り方に起因する可能性があり、厳密な実証のためには単一スクリプトからの再集計が今後の課題であるとする、学術的な限界（limitation）としての注釈を追記しました。

4.  **計算効率評価のプロファイリングに関する留保（6.5節）**
    *   **修正箇所**: 6.5節のTable Yの直下のパラグラフ。
    *   **内容**: Data-Free SST-Mergeが最速であるという理論的かつ定性的な結果には整合するものの、直接該当する実測プロファイリングログファイルが完全には確認できなかったため、Table Yに示された秒数の厳密な精度については実測ログによる直接的な再検証が望まれる旨を追記しました。

5.  **結論と今後の課題への反映（7章）**
    *   **修正箇所**: 7章のパラグラフ全体。
    *   **内容**: 生ログ検証により質的傾向やベースライン性能の妥当性が裏付けられた一方、一部でドメイン条件の混入や集計数値のブレが特定されたことを総括しました。今後の課題として、「実験条件ごとの表の分離」「単一集計スクリプトからの全表再生成」「プロファイリングログの完全公開」を明記し、論文自体の検証性を向上させる方針へとアップデートしました。
