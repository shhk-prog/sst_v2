## 統合方針

## 各セクションへの統合内容

### 6.1 Main Benchmark Results & Pareto Trade-off (RQ1)
* **ベースモデルの整合性**: 冒頭の評価結果の説明部分に、WizardMath (39.38%) や SafetyFT (7.19%) などのベースモデル単体の性能が、GitHubリポジトリの生ログ (`results/debug_limit320/base/`) と完全に一致し、ベースライン評価の信頼性が確認された旨を追記します。
* **Table 3 DELLAの帰属誤り**: 前回の修正でTable 3のDELLAの数値を正常値（Appendix準拠）に修正し注記を入れましたが、本文中にも段落を追加し、「以前の版でTable 3に記載されていたDELLAの完全崩壊データは、実は `safety+math` (2ドメイン) の結果ではなく `safety+math+code+medical` (4ドメイン) の結果が混入したものであった。実際の2ドメイン環境ではDELLAは健全に機能している」という検証結果を明記します。

### 6.2 臨界点転移と「偽の安全性」の排除
* **崩壊メカニズムの条件切り分け**: DELLAやDAREに見られるような深刻な「推論完全崩壊（全出力がGibberish化する現象）」は、一般的な臨界点転移というよりも、4ドメイン同時マージのような**極めて干渉負荷の高い条件下で特異的に観測される現象**であることを明記します。これにより、読者に「2ドメインでも常に崩壊する」という誤解を与えないよう条件を切り分けます。

### 6.3 出力崩壊のメカニズムと正常応答に基づく Pareto AUC 評価
* **GSM8K数値の不整合**: 提案手法 (Diagonal SST) のGSM8Kの数値について、Table 3記載値（例: α=0.2で42.81%）と、実際の生ログ（37.81%）、およびAppendix記載値との間に数ポイントの食い違いがあることを明記します。集計スクリプトの版違いやシード平均の取り方の差異が原因と考えられるため、再集計の必要性があるという学術的な留保（limitation）として追記します。

### 6.5 計算効率と頑健性 (RQ4, RQ5)
* **計算時間についての留保**: Table Yに示されたData-Free SST-Mergeの実行時間（107秒）は理論的オーダーと整合するものの、実測プロファイリングログファイルが直接確認できていないため、秒数の厳密な精度については実測ログによる再検証が望まれる旨を追記します。

### 7. Conclusion & Future Work
* 結論部分において、「生ログとの照合により、質的傾向やベース性能の妥当性は確認された一方で、一部の表におけるドメイン条件の混入（DELLA）や集計数値の揺らぎ（GSM8K）が特定された」ことを総括します。
* 今後の課題（Future Work）として、「実験条件（ドメイン数）ごとに表を明確に分離すること」「単一の集計スクリプトから全表を再生成し版の食い違いを排除すること」「プロファイリングログを完全公開すること」の3点を追加します。
