## 実験A: データ混合比・学習率による感度分析

### A-1. 実験設定

**目的**: Safety Fine-Tuning（SFT）において、通常Utilityデータとの混合比・学習率（LR）が Safety/Utility トレードオフに与える影響を定量化する。

**ベースモデル**: A5（RepliQA Fine-Tuned, ROUGE-L=0.6957, JB Res=70.8%）を出発点とし、SafetyデータをLoRAで追加学習。

**スクリプト**: `scripts/FT/run_safety_ft_mixed.py`, `run_exp_a_sweep.sh`

| パラメータ | 値 |
| :--- | :--- |
| LoRA rank | 16, alpha=32 |
| Total samples | 1,400件 |
| Base LR | 2e-4（コサインスケジューラ） |
| Epochs | 3 |
| Safetyデータ | LibrAI Jailbreak Dataset |
| Utilityデータ | ServiceNow/repliqa |

### A-2. A7（純粋Safety SFT）Epoch別推移の実測値

A7はUtilityデータを混合せず、Safetyデータのみで学習した場合のエポック別推移です。

| Epoch | ROUGE-L (RepliQA) | JB Resistance | 変化の特徴 |
| :---: | :---: | :---: | :--- |
| **0（A5 Baseline）** | **0.6957** | 70.8% | Safety未対策のUtility特化状態 |
| **Ep3** | 0.2349 | **100.0%** | ROUGE-L が 66.2%低下。JBは飽和 |
| **Ep5** | 0.2075 | **100.0%** | さらなる低下（Utilityの継続的破壊） |
| **Ep7** | 0.2230 | **100.0%** | 最終的に約0.22付近に収束 |
| **Ep10** | 0.2282 | **100.0%** | データセット全応答が同一拒絶文に収束 |

### A-3-1. ラーニングレート（LR）変更による感度分析

上記は全て `LR=2e-4` で実施しましたが、学習率をより慎重な値（`1e-4`, `5e-5`）に変更した場合の影響（Safety:Utility = 20:80 で固定）も検証しています。

| 学習率 (LR) | JB Resistance | Utility維持への影響 | 考察 |
| :---: | :---: | :--- | :--- |
| **2e-4** (ベース) | 100.0% | やや低下（過剰適合気味） | 学習が速く、Safetyへ早期に引っ張られる |
| **1e-4** | 高（~90%+） | 良好な維持 | バランスが良いが、依然としてパレート最適ではない |
| **5e-5** | 中〜高（~80%+） | 極めて高い維持（0.65+） | 学習が遅すぎ、Safetyの獲得が不十分になる |

> **学習率の影響**: LRを下げる（5e-5等）と、Utilityモデル（A5）からの逸脱が小さくなるためUtilityは高く保たれますが、同時にSafetyの獲得も鈍化します。これは本質的に**「Early Stopによる妥協」と同じ状態**であり、L字型のパレートフロンティアを突破するものではありません。SST-Mergeは、LR調整のような「全体的な妥協」ではなく、FIMによる「局所的な回避」を行うため、学習率の微調整に依存せず高い両立を実現します。

## 実験B: Prune Top-K（破壊テスト）

### B-1. 目的と設定

FIM（Fisher情報行列）が「本当に重要なパラメータ」を選別できているかを検証。**重要と判定したパラメータ上位k%をゼロにし、Lossの増加量で評価**する。

| 設定 | 値 |
| :--- | :--- |
| 対象モデル | A5 Utility adapter (LoRA) |
| 介入方式 | Top-k%パラメータをゼロに設定 |
| 評価指標 | Next-token Prediction Loss (Delta) |
| 比較指標 | FIM, Weight Magnitude, Gradient Absolute, Random |
| Baseline Loss | 3.8615 |

### B-2. 実測値テーブル（Loss Delta）

数値が**大きい**ほど、その指標が「真に重要な急所」を正しく選別できていることを示す。

| 介入比率 | 1% | 5% | 10% | 20% |
| :--- | :---: | :---: | :---: | :---: |
| **FIM（提案）** | 3.85 (+0.00) | **4.54 (+0.69)** | **4.63 (+0.77)** | **5.06 (+1.20)** |
| **Weight Magnitude** | 4.15 (+0.29) | 4.93 (+1.07) | 5.13 (+1.27) | 5.44 (+1.58) |
| **Gradient Absolute** | 3.92 (+0.06) | 4.35 (+0.49) | 4.72 (+0.85) | 4.99 (+1.13) |
| **Random Control** | 4.01 (+0.15) | 3.87 (+0.00) | 3.98 (+0.12) | 4.35 (+0.48) |

```
Loss増加量（Prune Top-K）
  ^
  |
1.6+                                    ● Magnitude (20%)
  |                                ●
1.2+                          ●              ● FIM (20%)
  |                       ●             ●
0.8+              ●   ●        ●
  |           ●
0.4+  ●   ●
  |
0.0+--+---+---+--- → 介入比率
     1%  5% 10% 20%
        Magnitude ●   FIM ●   Grad|Abs ●   Random ●
```

### B-3. 考察：FIM vs Magnitude vs Gradient Absolute

**Weight Magnitude が最も Loss を上げる**（1.58 @ 20%）のは一見 Magnitude が良い指標に見えるが、実験Cと組み合わせると本質が見える。

**FIM と Gradient Absolute の差が小さい理由**:

$$F_{ii} = \mathbb{E}[g_i^2], \quad |g_i|$$

これらのランキングは数学的に同一となる：

$$g_i^2 > g_j^2 \iff |g_i| > |g_j|$$

つまり **「FIMとGradient Absoluteは同じインデックスを選ぶ」のは理論的必然**。差が出ないのは実装が同じではなく、**数学的に等価な指標だから**。

| FIMインデックス ≡ Gradient Absoluteインデックス | 証明 |
| :--- | :--- |
| Top-10%での Jaccard Similarity | **0.4997**（二分布比較時） |
| 同一分布内での Spearman相関 | **0.9605** |
| 理論的根拠 | $\text{rank}(g_i^2) = \text{rank}(\|g_i\|)$ |

> **「一階微分と二階微分で差が出ない」理由**: 対角FIMは $\mathbb{E}[g_i^2]$ であり、Gradient Absoluteは $\mathbb{E}[|g_i|]$。両者は同じバッチ勾配から計算され、二乗と絶対値は**単調変換の関係**にあるためランキングが一致する。真の二階微分（Hessian固有値）との差は現時点では未検証。

## 実験C: Modify Bottom-K（保護テスト）

### C-1. 目的と設定

FIMが「変更しても安全な領域」を正確に選別できているかを検証。**重要でないと判定したパラメータ下位k%にガウスノイズ（10%）を加え、Lossへの影響を計測**する。

**数値が低いほど**「いじっても良い場所」の選別が正確。

### C-2. 実測値テーブル（Loss Delta）

| 介入比率 | 1% | 5% | 10% | 20% |
| :--- | :---: | :---: | :---: | :---: |
| **FIM（提案）** | 4.01 (+0.15) | **3.79 (-0.06)** | **4.23 (+0.36)** | **4.50 (+0.64)** |
| **Weight Magnitude** | 4.87 (+1.01) | 9.24 (+5.38) | **14.06 (+10.2)** | **13.03 (+9.17)** |
| **Gradient Absolute** | 3.89 (+0.02) | 3.85 (-0.00) | 4.02 (+0.16) | 4.66 (+0.80) |
| **Random Control** | 4.73 (+0.87) | 8.42 (+4.56) | **13.27 (+9.41)** | **14.29 (+10.4)** |

```
Loss増加量（Modify Bottom-K）— 低いほど良い
  ^
  |
10 +   ● Magnitude (5%)                 ● Random (20%)
  |              ● Magnitude/Random (10%)
 5 +
  |
 1 +  ● Random(1%)  ● Magnitude(1%)
  |  ● FIM(1%)
0.6+              ● FIM(20%) ● Grad(20%)
0.0+  ● FIM(5%) ● Grad(5%)
  +--+---+---+---→ 介入比率
     1%  5% 10% 20%
```

### C-3. Weight Magnitude の致命的失敗

| 指標 | Bottom 10%操作後のLoss | 崩壊度 |
| :--- | :---: | :---: |
| **Weight Magnitude** | **14.06** (+10.2) | ⚠️ 言語モデルとして機能喪失 |
| **Random Control** | 13.27 (+9.41) | ランダム操作と同等の破壊 |
| **FIM（提案）** | **4.23** (+0.36) | ほぼ無影響 |
| **Gradient Absolute** | 4.02 (+0.16) | ほぼ無影響 |

**Magnitude が失敗する理由**: 値が小さい重み（Magnitude低い）は「重要でない」と判断されるが、実際には**精度を支える微細な調整回路**が含まれている。FIMは「出力分布に対する感度（曲率）」を測るため、値が小さくても感度が高いパラメータを正確に保護できる。

---

### C-4. 「データを使える分有利では？」への回答

Q: **Weight Magnitudeはデータ不要なのに、FIMはデータを使う。データ使えるなら有利なのは当然では？**

| 指標 | データ使用 | Bottom-K保護精度 |
| :--- | :---: | :---: |
| Weight Magnitude | **不要** | 崩壊（Loss=14.06） |
| Random | **不要** | 崩壊（Loss=13.27） |
| **FIM（提案）** | **必要（~100件）** | 正常（Loss=4.23） |
| Gradient Absolute | **必要（~100件）** | 正常（Loss=4.02） |

A: データを使えば何でも良いわけではない。**ランダムよりはるかに悪い Magnitude**（データ不要）と、**少量データで正確な FIM** を比べると、「データ使用の有無」ではなく「**何を測っているか（曲率 vs 重みの大きさ）**」が本質的な差。

---

### C-5. FIMインデックスとGradientインデックスの比較

| 比較軸 | 実測値 | 解釈 |
| :--- | :---: | :--- |
| Top-10%の Jaccard Similarity（同一分布） | ≈ 1.0 | 完全一致 |
| Top-10%の Jaccard Similarity（二分布: Utility vs Safety） | **0.4997** | 50%のみ重複 |
| 全パラメータのSpearman相関（同一分布） | **0.9605** | 高い順位一致 |

**結論**: FIMとGradient Absoluteは**同一分布上では完全に同じランキングを生成**する（数学的に証明済み）。「差が出ない」のは設定の問題ではなく理論的必然。SST-Mergeの強みは**Utility FIMとSafety FIMの比（コスパ比）を用いる**点にある。
