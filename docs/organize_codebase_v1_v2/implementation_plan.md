# 実装計画: v1とv2コードベースの整理

本計画は、レガシーである `v1` コードベースと、新しい `v2` コードベース（旧 `v2_experiments`）をそれぞれ独立したディレクトリにきれいに分離する手順を示します。

## 提案する変更内容

トップレベルに `v1` および `v2` の2つのディレクトリを作成します。Gitのコミット履歴を保持するため、移動には `git mv` を使用します。

### ディレクトリ構成の変更

#### [NEW] v1/
以下のアイテムをこのディレクトリに移動します：
- **ディレクトリ**: `archive/`, `core/`, `data/`, `eval/`, `logs/`, `scratch/`, `scripts/`, `tests/`
- **ファイル**: `README.md`（移動後は `v1/README.md` になります）、ルートにある全ての `*.py`, `*.sh`, `*.json`, `*.csv`, `*.txt`, `*.tex`

#### [RENAME] v2_experiments -> v2/
命名規則を統一するため、`v2_experiments` を `v2` にリネームします。

#### [NEW] README.md (ルート)
リポジトリが `v1` と `v2` に分割されたことを説明するシンプルな `README.md` をトップレベルに新しく作成します。（日本語）

#### [KEEP AT ROOT]
以下のファイルおよびフォルダは、ルートディレクトリにそのまま残します：
- `docs/`（ユーザーの指定によりルートに残します）
- `.git/`
- `.gitignore`
- `.vscode/`
- `venv_sst/`（新しく作成された仮想環境）

## 検証計画

### 手動による検証
1. `git status` を実行し、すべての移動が正しくステージングされているか確認します。
2. `ls -la` を用いてディレクトリ構造を確認します。
3. 仮想環境 `venv_sst` が無傷で機能しているか確認します。
