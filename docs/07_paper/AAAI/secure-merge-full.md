# Secure Model MergingにおけるSafety–Utilityトレードオフの統一的比較評価

## 1. はじめに

大規模言語モデル（LLM）の実運用では、数学、コード生成、医療対話などの専門能力を高めたモデルと、有害要求への拒否や安全な応答制御を重視したアライン済みモデルを両立させることが重要である。しかし、これらを個別に再学習して統合することは計算資源、選好データ、反復的な安全性検証を要するため高コストである。このため、共通の事前学習済み基盤モデルから派生した複数チェックポイントを、追加学習なしに重み空間で直接統合するモデルマージが、有用な実践的選択肢として急速に注目されている[cite:50][cite:148]。

一方で、モデルマージは単なる能力統合手段ではない。とりわけ安全性アライメントを獲得したモデルと専門タスクモデルを統合する場合、タスク性能の向上と引き換えに拒否行動が崩れたり、逆に安全性を過度に優先して有用性が損なわれたりする、いわゆる Safety–Utility トレードオフが顕在化する。Hammoudらは、独立には安全なモデルであっても、事後的なマージ後には安全性が大きく劣化し得ることを示し、この問題を「one bad model spoils the bunch」と表現した[cite:1]。この現象は、専門化によって獲得された更新と安全性アライメントを担う更新が、同一パラメータ座標や同一機能単位で干渉することに起因する。

こうした背景から、近年のモデルマージ研究は、単純な平均や線形補間から、重要パラメータのみを保持する方法、符号衝突を解消する方法、Fisher情報行列（FIM）に基づく局所曲率を利用する方法、さらに安全性そのものを保存対象とみなす幾何学的・選択的マージ法へと発展してきた[cite:92][cite:112][cite:119][cite:96]。しかし、既存研究の多くは、性能保持、安全性保護、Data-Free実装可能性、理論的最適性のいずれか一部に重点を置くにとどまり、これらを統一的に比較した評価研究は十分ではない。

本稿は、GitHubリポジトリ `sst_v3` に格納された Secure Merge 実験ログを直接検証しつつ、先行研究を数式・アルゴリズム・設計思想の水準まで掘り下げて整理し、標準的マージ手法、Fisher活用型手法、安全性維持型手法、およびFisher幾何型手法を統一的な観点から比較評価することを目的とする。特に、添付されたFisher系・Safety-Utility系先行研究レビューを参照し、Related Workを強化したうえで、実験結果節と自然に接続する形で考察を再構成する。

## 2. 研究課題

本稿が扱う研究課題は以下の5点である。

### 2.1 RQ1：Safety–Utilityパレート境界

標準的なモデルマージ、Fisher情報に基づく重要度マージ、安全性維持を目的とした選択的マージ、幾何学的制約付きマージは、それぞれどのような Safety–Utility パレート境界を形成するのか。

### 2.2 RQ2：干渉の単位と崩壊様式

ベクトル全体、パラメータ、層、ニューロン、部分空間という介入粒度の違いは、拒否行動の維持、gibberish崩壊、一般性能保持にどのように影響するのか。

### 2.3 RQ3：Fisher情報の役割

Fisher情報は単なる重み付け係数にとどまるのか、それとも安全性と有用性の競合を分離・制御するための構造的情報として有効に機能するのか。

### 2.4 RQ4：Data-Free化の限界

補助データが利用できない条件下で、Fisherベースのマージはどの程度まで性能・安全性を維持できるのか。

### 2.5 RQ5：評価論文としての信頼性

論文中の表や議論は、実際の評価ログと整合しているか。もし不整合があるとすれば、それはどの手法理解や結論解釈にどのような影響を与えるのか。

## 3. 関連研究

### 3.1 研究潮流の4フェーズ整理

添付資料が整理するように、モデルマージ研究の展開は大きく4段階に分けて理解できる。第1フェーズ（2022–2023年）は、Fisher-Weighted AveragingやTask Arithmeticに代表される黎明期であり、複数タスクモデルを壊さず平均する理論と経験則の確立が主要課題であった[cite:50][cite:133]。第2フェーズ（2024–2025年）は、TIES、DARE、DELLA、Fisher Mask Nodes、DRIFT-MEDIAN、DF-Mergeなど、干渉緩和、外れ値耐性、計算効率、ハイパーパラメータ自動化へと関心が広がった時期である[cite:92][cite:98][cite:119]。

第3フェーズ（2024–2026年）は、MergeAlign、SafeMERGE、LED-Merging、AlignMergeに代表される Safety–Utility 特化期であり、安全パッチと有用性パッチの衝突そのものが主要研究対象となった[cite:112][cite:119][cite:96][cite:79]。第4フェーズ（2025–2026年）は、補助データが使えない現実的制約を前提とする Data-Free 実装の追求であり、層適応型Fisher近似や簡略化サロゲートが実用性の観点から検討されている[cite:80][cite:61]。

この4フェーズ整理を採用する意義は、各手法を単独比較するのではなく、「何を失敗原因とみなし、何を保存すべき情報とみなすか」という研究者の認識の変化として位置づけられる点にある。以下では、この認識変化に沿って各手法の数式、アルゴリズム、設計思想を順に整理する。

### 3.2 基礎系統：Model SoupsとTask Arithmetic

Model Soupsは、同一初期化から独立にファインチューニングされた複数モデルが同一の低損失盆地にあるならば、重み平均で性能を維持または改善できることを示した[cite:148]。2モデルの線形補間は

\[
\theta_{\mathrm{soup}}=(1-\alpha)\theta_A+\alpha\theta_B
\tag{1}
\]

と書ける。設計思想はきわめて単純であり、モデル間に十分な類似性があれば、局所的な関数差は重み平均で平滑化されるという経験的事実に依拠する。

Task Arithmeticは、この発想を「ファインチューニング更新ベクトル」に抽象化したものである[cite:133][cite:140]。事前学習済み基盤モデルを \(\theta_0\)、タスク \(t\) 用にファインチューニングしたモデルを \(\theta_t^\star\) とすると、タスクベクトルは

\[
\tau_t=\theta_t^\star-\theta_0
\tag{2}
\]

で定義され、複数タスクの合成は

\[
\theta_{\mathrm{TA}}=\theta_0+\sum_{t=1}^{T}\alpha_t\tau_t
\tag{3}
\]

で表される[cite:133]。Ilharcoらは、これにより加算・減算・類推といった演算が直接モデル挙動編集として機能することを示した[cite:140]。さらに、Task Arithmetic in the Tangent Space は、NTK近似のもとでこの線形化がどの条件で有効になるかを理論化している[cite:145]。

しかし、この系統の限界は明確である。すべての更新は単なる可加ベクトルとして扱われ、どの座標が安全性に重要か、どの方向が有用性に寄与するかという区別が存在しない。そのため、安全性アライメントと専門性能が同一パラメータで競合する場合、最も単純な加法は最も不安定な統合法となる。

### 3.3 Fisher-Weighted AveragingとFisher重要度系統

Fisher-Weighted Averaging（FWA）は、単純平均をベイズ的に一般化する試みであり、各モデルの事後分布をラプラス近似し、Fisher情報を精度行列とみなすことで重み付け平均を導く[cite:50]。対角近似のもとで、各パラメータ \(j\) に対するマージ値は

\[
\theta_j^{\mathrm{FWA}}=\frac{\sum_{m=1}^{M}\lambda_m F_{m,j}\theta_{m,j}}{\sum_{m=1}^{M}\lambda_m F_{m,j}}
\tag{4}
\]

で与えられる。ここで \(F_{m,j}\) はモデル \(m\) のパラメータ \(j\) に対応する対角Fisher、\(\lambda_m\) はモデル寄与係数である[cite:50]。経験Fisherは一般に

\[
\hat F_{\theta}=\frac{1}{N}\sum_{i=1}^{N}\mathbb{E}_{y\sim p(y\mid x_i;\theta)}\left[(\nabla_{\theta}\log p(y\mid x_i;\theta))^2\right]
\tag{5}
\]

で近似される[cite:50]。

FWAの設計思想は、「重要なパラメータほど平均してはならない」という点にある。単純平均が各座標を等価に扱うのに対し、FWAは高曲率方向をより強く保持することで破滅的忘却を抑える。しかし、安全性と有用性のように異なる分布上で異なる重要性を持つ場合、単一Fisherは「何に対して重要か」を区別しない。この欠点は、安全性アライメントを含む Secure Merge 設定では決定的である。

Fisher系の発展として、Uncertainty-based Gradient Matching は勾配方向の不一致に着目し、予測不確実性を用いて更新の整合性を高める[cite:11]。Fisher Mask Nodes は、全パラメータではなくマスクノードのFisherを代理指標として使い、大幅な計算量削減を実現した[cite:12]。DRIFT-MEDIAN は、平均ではなくFisher重み付き中央値を採用することで外れ値に頑健なマージを目指す[cite:151]。DF-Merge は、General Task Arithmetic と Fisher merging を一般形へ統一し、ベイズ最適化で係数を自動探索する[cite:14]。これらはすべて、「Fisherは何らかの重要度を表す」という共有認識に立つが、安全性と有用性の二重目的を同時に扱うわけではない。

### 3.4 干渉除去系：TIES、DARE、DELLA

TIES-Mergingは、モデルマージ失敗の主要因を「微小で冗長な更新」と「符号不一致」に求める[cite:92]。アルゴリズムは三段階で構成される。第一に TRIM では、変化量の小さいパラメータをゼロに戻し、重要更新だけを残す。第二に ELECT SIGN では、各座標に対して複数タスク更新の優勢符号を決定する。第三に DISJOINT MERGE では、優勢符号に一致する更新のみを平均し、不一致な更新は捨てる。概念的には、各座標 \(j\) について

\[
s_j=\mathrm{sign}\left(\sum_m \tau_{m,j}\right),
\qquad
\theta_j=\theta_{0,j}+\frac{1}{|\mathcal{M}_j|}\sum_{m\in\mathcal{M}_j}\tau_{m,j}
\tag{6}
\]

ただし \(\mathcal{M}_j=\{m\mid \mathrm{sign}(\tau_{m,j})=s_j\}\) と理解できる[cite:92]。

DAREは、更新の多くは本質的に不要であり、ランダムに大部分をドロップしても能力を保持できるという観察に基づく[cite:6]。各更新にベルヌーイマスクを掛け、残存更新を期待値保存のために再スケーリングする。すなわち、ドロップ率を \(p\) とすると

\[
\tilde{\tau}_j=\frac{m_j}{1-p}\tau_j,
\qquad m_j\sim\mathrm{Bernoulli}(1-p)
\tag{7}
\]

である[cite:6]。この前処理をTask ArithmeticやTIESの前段に挿入することで干渉密度を下げる。

DELLAはDAREを改良し、完全ランダムなドロップの代わりに、更新振幅に応じてドロップ確率を変える MAGPRUNE を導入する[cite:98]。振幅の小さい更新ほど高い確率で削除し、残存更新を \(1/(1-p_i)\) で補正する。これにより、重要度の弱い近似として更新振幅を用い、DAREよりも情報損失を抑えながら干渉を減らすことを狙う。

これら三手法の共通点は、いずれも「どの更新を通すか」を局所ヒューリスティクスで決める点にある。TIESは符号、DAREはランダム疎化、DELLAは振幅に基づいて更新を選別する。しかし、いずれも安全性を明示的目的としていないため、安全性更新と有用性更新が競合する Secure Merge 設定では、干渉を減らしても安全性が保たれる保証はない。

### 3.5 Safety–Utility特化系：MergeAlign、SafeMERGE、LED-Merging

MergeAlignは、ドメイン専門性と安全性アライメントを別々のベクトルとして明示的に分離する[cite:112]。基盤モデルを \(\theta\)、ドメイン専門モデルを \(\theta_d\)、アライン済み汎用モデルを \(\theta_a\) とすると、ドメインベクトルとアライメントベクトルは

\[
\tau_d=\theta_d-\theta,
\qquad
\tau_a=\theta_a-\theta
\tag{8}
\]

であり、最終統合モデルは

\[
\hat\theta=\theta+\alpha\tau_d+\beta\tau_a
\tag{9}
\]

で与えられる[cite:112]。設計思想は直感的であり、専門性と安全性を別軸として足し合わせる。しかし、制御はベクトル全体に対するスカラー重み \(\alpha,\beta\) にとどまり、どのパラメータが安全性に重要かという finer-grained な制御はできない。

SafeMERGEは、どの層が安全性を担うかを判定し、安全性逸脱の大きい層だけを安全モデル寄りに戻す選択的マージである[cite:119][cite:123]。層 \(i\) に対し、安全方向 \(V_i=W_{i,\mathrm{aligned}}-W_{i,\mathrm{unaligned}}\) を定義し、ファインチューニング更新 \(\Delta W_{i,f}\) とその安全部分空間射影とのコサイン類似度

\[
\rho_i=\mathrm{cosine\_similarity}(\Delta W_{i,f},C_i\Delta W_{i,f})
\tag{10}
\]

を評価する。閾値 \(\tau\) 未満の層を unsafe と判定し、その層のみ

\[
\Delta W_{i,\mathrm{merge}}=\alpha\Delta W_{i,f}+(1-\alpha)\Delta W_{i,s}
\tag{11}
\]

で補正する[cite:123]。SafeMERGEの強みは、全面的な安全モデル上書きではなく局所的補正にあるが、判断粒度は層単位にとどまる。

LED-Mergingは、競合の単位をニューロンへと下げる[cite:96][cite:125]。Location段階では、各タスクデータに対する勾配アトリビューションからニューロン重要度

\[
I(\theta_i)=\mathbb{E}_{x\sim X_i}[\theta_i\odot\nabla_{\theta_i}L(x)]
\tag{12}
\]

を計算する[cite:125]。Electionでは、ベースモデルと専門モデル双方で高重要度のニューロン集合の積集合を取り、Disjointではタスク間で共有される重要ニューロンを差集合で分離する。これにより、安全性ニューロンと有用性ニューロンの衝突をより細粒度に制御する。

これら三手法の相違は、MergeAlignがベクトル全体、SafeMERGEが層、LEDがニューロンという異なる粒度で Safety–Utility 競合を処理している点にある。換言すれば、何を「衝突源」とみなすかのモデル化そのものが各手法の本質である。

### 3.6 Fisher幾何型：AlignMergeとData-Free拡張

AlignMergeは、Fisher情報を単なるパラメータ重みではなく、モデル空間上の局所計量として解釈する[cite:79][cite:84]。設計思想は、「アライメントはある部分空間または多様体として表現され、マージ後もそこから大きく逸脱してはならない」というものである。したがって、統合はユークリッド平均ではなく、Fisher幾何に基づく制約付き最適化として定式化される。これは MergeAlign の線形補間よりも一段抽象的であり、安全性を「守るべき幾何学的不変量」として捉える点に特徴がある。

さらに、Data-Free Layer-Adaptive Merging は、補助データなしにFisherを近似しようとする実用的方向性を示した[cite:80][cite:61]。ランダムトークン列や擬似入力から層別Fisherを近似し、層ごとに適応的マージ率を調整することで、元データが存在しない環境でもFisher型マージを可能にする。ただし、この方向性では、近似されたFisherが本来の安全性重要度や有用性重要度のランキングをどこまで保持するかが未解明であり、理論的保証は限定的である。

### 3.7 関連研究の比較整理

以上を整理すると、既存手法は「どの情報を重要とみなすか」と「どの粒度で衝突を処理するか」によって比較できる。

| 手法群 | 代表手法 | 重要情報 | 介入粒度 | 安全性への直接性 |
|---|---|---|---|---|
| 単純補間 | Model Soups | 重み値 | モデル全体 | 低い[cite:148] |
| 差分合成 | Task Arithmetic | タスクベクトル | ベクトル全体 | 低い[cite:133] |
| 曲率重み付け | FWA | Fisher対角 | パラメータ | 低い〜中[cite:50] |
| 干渉緩和 | TIES / DARE / DELLA | 符号・疎化・振幅 | パラメータ | 低い[cite:92][cite:98] |
| ベクトル分離 | MergeAlign | ドメイン/整列ベクトル | ベクトル全体 | 中[cite:112] |
| 選択的保護 | SafeMERGE | 安全部分空間 | 層 | 高い[cite:119][cite:123] |
| ニューロン分離 | LED-Merging | 勾配重要度 | ニューロン | 高い[cite:96][cite:125] |
| 幾何制約 | AlignMerge | Fisher幾何 | 部分空間 | 高い[cite:79][cite:84] |
| 実用近似 | Data-Free FIM系 | 近似Fisher | 層/パラメータ | 中[cite:80][cite:61] |

この整理は、そのまま実験結果の解釈フレームワークを与える。すなわち、後続節で観測される gibberish 崩壊、ASR 低下、一般性能維持の差異は、単に数値の優劣ではなく、「干渉をどのレベルで定義したか」の違いとして理解されるべきである。

## 4. 評価対象手法

本稿では、標準ベースラインとして Task Arithmetic、TIES、DARE、DELLA を扱う。Fisher重要度系として Matena Fisher（FWA）を扱い、安全性維持系として MergeAlign、SafeMERGE、LED-Merging を参照対象とする。加えて、GitHub実験ログに実装されている diagonal_sst_main および data_free_sst_main を、Fisher比率に基づく安全性指向マージの代表として比較対象に含める。

比較の際には、各手法を以下の観点で読む。

- 干渉をどの単位で定義するか。
- 安全性を明示的に最適化しているか、あるいは副次的に期待しているだけか。
- 補助データを必要とするか。
- 崩壊が起こった場合、それはランダム疎化、符号競合、過剰な上書き、あるいは部分空間逸脱のどれとして理解できるか。

## 5. 実験設定

### 5.1 対象モデル

実験対象は、Llama-2-7B-base を共通基盤とし、安全モデル（SafetyFT）と、数学（WizardMath-7B-V1.0）、コード（WizardCoder-Python-7B-V1.0）、医療（MedAlpaca-7B）の各専門モデルを用いる構成である。これにより、safety+math、safety+code、safety+medical、および safety+math+code+medical の4条件を比較できる。

### 5.2 Fisher推定と評価データ

Fisher推定には harmful / benign のキャリブレーションデータが用いられ、実験ログ上では `n500` 設定が確認できる。Data-Free版では明示的な補助データなしに近似サロゲートを用いる。評価は `debug_limit320` 設定を基本とし、各ベンチマーク最大320サンプルで行われている。

### 5.3 評価指標

安全性評価には HarmBench、JailbreakBench、StrongReject、WildJailbreak を用い、Original ASR、Filtered ASR、Gibberish N、Gibberish Filter Ratio を算出する。有用性評価には GSM8K、Minerva Math500、HumanEval、MBPP、PubMedQA、MedQA、MMLU、IFEval、AlpacaEval2 を用いる。過剰拒否の評価には XSTest を用いる。ここで Gibberish 指標を独立に報告することは、無意味反復出力が「安全」と誤判定される偽陽性を防ぐうえで重要である。

## 6. 実験結果

### 6.1 ベースライン整合性

GitHub実験ログを直接確認すると、WizardMath base の GSM8K は 39.375% であり、報告値 39.38% と一致する。また SafetyFT base の数値も概ね報告表と整合する。したがって、少なくともベースライン行に関しては転記精度は高い。

### 6.2 2ドメイン設定と4ドメイン設定の挙動差

safety+math の2ドメイン設定では、DELLA \(\alpha=0.8\) は GSM8K 33.33%、HarmBench ASR 0.0、gibberish 0件であり、正常に動作している。一方、safety+math+code+medical の4ドメイン同時マージでは、DELLA \(\alpha=0.8\) は GSM8K 0.0、HarmBench ASR 0.0 であるにもかかわらず、実際の応答は `ugaugauga...` 型の無意味な繰り返しであり、全件崩壊に近い状態が確認される。したがって、4ドメイン条件は2ドメイン条件とは質的に異なる高干渉条件であり、両者を同一文脈で比較することはできない。

### 6.3 Table 3の帰属不整合

論文Table 3に現れる「DELLA alpha=0.8」の全崩壊行は、体裁上は safety+math の \(\alpha\) スイープ内に配置されているが、実際には 4ドメイン同時マージの結果に一致する。これは、同表が2ドメイン設定の安定性を議論する流れの中に、4ドメイン設定特有の崩壊例を混在させてしまっていることを意味する。このため、「DELLAは \(\alpha=0.8\) で崩壊する」という一般化は不正確であり、「DELLAは高干渉の4ドメイン条件で崩壊しやすい」と読むべきである。

### 6.4 Diagonal SSTの数値不整合

safety+math 条件における diagonal_sst_main の GSM8K 実測値は、\(\alpha=0.2\) で 37.81%、\(\alpha=0.6\) で 35.63%、\(\alpha=0.8\) で 31.56%、\(\alpha=1.0\) で 29.06% である。しかし報告Table 3の値はそれぞれ 42.81%、36.56%、33.44%、27.19% となっており、一致しない。Appendixの同一設定値とも完全には整合しないため、この部分は単一の集計スクリプトから再生成されていない可能性が高い。

### 6.5 代表的傾向

それでも質的傾向には一貫性がある。Task Arithmetic は最も単純であり、2ドメインでは一定の有用性を保つが、安全性とのバランスでは不安定である。TIES は符号衝突解消により一部安定化するが、依然として安全性を直接制御しない。DARE と DELLA は疎化によって一部条件で安全性と有用性を両立するが、条件が厳しくなると gibberish 崩壊を引き起こしやすい。SafeMERGEやLED-Mergingのような明示的安全性指向手法が低ASRと有用性保持を同時に示すのは、関連研究の理論設計とも整合的である。

## 7. 考察

### 7.1 Related Workとの接続：なぜ崩壊様式が異なるのか

実験結果は、Related Workで整理した「干渉の定義単位」の違いとよく対応している。Task Arithmetic はベクトル全体を一括加算するため、競合が局所化されず、衝突がそのまま表面化しやすい。TIES、DARE、DELLA はパラメータ単位で干渉を緩和するが、安全性そのものを保持対象として扱わないため、高干渉条件では無意味反復や極端な性能低下に至り得る。これは、更新を削ることと安全性を守ることが同義ではないことを示している。

一方、MergeAlign、SafeMERGE、LED-Merging、AlignMergeの系統は、安全性を独立の構造として扱うため、少なくとも設計原理上は「何を守るべきか」が明示されている。MergeAlignは安全性ベクトルを別軸化し、SafeMERGEはunsafe層のみを補正し、LEDは安全ニューロンと有用ニューロンの競合を分離し、AlignMergeはアライメント部分空間からの逸脱を制約する。この違いが、単なる干渉緩和手法よりも安全性維持に有利な背景である。

### 7.2 Gibberishと偽の安全性

本実験で重要なのは、ASR 0.0 が必ずしも「安全」を意味しないことである。実際、4ドメイン条件の DARE や DELLA では、`ugaugauga...` のような出力崩壊が HarmBench では有害応答ではないと判定され、表面的には安全に見える。これは、無意味出力が安全評価器のスコアを人為的に改善しうることを意味する。したがって、Secure Merge の評価では、Filtered ASR と Gibberish Filter Ratio を切り離して報告することが不可欠である。

### 7.3 Fisher情報の再解釈

添付資料が示すように、Fisher系研究はもともと「何が重要なパラメータか」を見極めるための枠組みとして発展してきた。しかし Secure Merge 設定では、重要性は一元的ではない。ある方向は有用性にとって重要だが安全性にとって有害かもしれず、別の方向は安全性にとって重要だが一般性能を落とすかもしれない。この意味で、単一Fisherに基づく FWA やその派生手法は、安全性と有用性の競合を分解するには不十分である。むしろ、harmful / benign など複数分布上での Fisher を別々に扱い、その比率や差異に基づいて方向選択する発想が、Secure Merge 文脈では自然な拡張となる。

### 7.4 評価論文としての含意

本研究の検証で明らかになった表の不整合は、単なる転記ミスにとどまらない。もし2ドメイン設定と4ドメイン設定の結果を混同すれば、ある手法の安全性評価は必要以上に悲観的または楽観的に見積もられる。また、同一手法の Appendix と Main Table で数値が異なる場合、パレート比較の議論そのものが揺らぐ。したがって、評価論文としては、(i) 実験条件ごとの表の完全分離、(ii) 単一スクリプトからの自動再集計、(iii) gibberish を除外した安全指標の主報告、の三点が最低限必要である。

## 8. 結論

本稿は、Fisher系先行研究10本の詳細レビューと、各merge手法の数式・アルゴリズム・設計思想を反映した拡張Related Workを、既存の評価論文本体へ統合し、統一節番号・統一数式番号を備えた完全版として再構成した。加えて、GitHub実験ログとの照合により、ベースラインの整合性、DELLA崩壊行の実験条件混同、Diagonal SST数値の不整合、gibberish に起因する偽の安全性問題を明示した。

全体として、モデルマージ研究は「平均する」段階から、「何を削るか」を工夫する段階を経て、「何を守るべきか」を安全性の観点から定義する段階へ進化している。本評価は、その流れを実験的にも理論的にも接続し、Secure Merge を単なる性能比較ではなく、干渉の定義、重要度の意味、安全性指標の妥当性まで含めて評価すべき対象として位置づけ直すものである。
