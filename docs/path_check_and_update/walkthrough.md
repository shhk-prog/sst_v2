# パス管理修正の確認結果

プロジェクト全体のパス設定を `.env` で管理するように修正しました。

## 実施内容

### 1. 環境変数の設定
- `$HOME/src/.env` に `SST_HOME="/mnt/nas/home/hiromi/src/sst_v2"` を追加しました。

### 2. スクリプトの修正
- **v1 スクリプト**: 
  - `run_all_experiments.sh`, `run_experiment_optimized.sh` において、`.env` から `SST_HOME` をロードし、ディレクトリ移動や仮想環境の有効化に使用するように変更しました。
  - `v1/scripts/` 以下の Python スクリプト群（評価・分析用）に `load_dotenv` を導入し、ハードコードされていた `/mnt/iag-02/...` を `os.getenv("SST_HOME")` を利用した記述に置き換えました。
- **v2 スクリプト**: 
  - `run_phase2.sh`, `run_xstest_only.sh` において、仮想環境のパスを `SST_HOME` を優先して探すように修正しました。

### 3. ドキュメントの修正
- `docs/` 以下の Markdown, CSV, TXT ファイル内に残っていた古いパス（`/mnt/iag-02/...`）を、新しいパス（`/mnt/nas/...`）に一括置換しました。

## 確認済み事項
- `grep` による再確認を行い、ソースコード内（バイナリ・キャッシュを除く）に古い絶対パス `/mnt/iag-02/` が残っていないことを確認しました。
- `v2` の主要スクリプトが `.env` を正しくロードできる状態であることを確認しました。

## 今後の利用について
今後、別の環境にプロジェクトを移動した際は、`$HOME/src/.env` 内の `SST_HOME` を書き換えるだけで、スクリプトが正しく動作するようになります。
