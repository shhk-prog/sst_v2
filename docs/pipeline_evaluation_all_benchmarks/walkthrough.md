## 3. 分析と考察

### ① model1_math (Math FT) の TeleQnA 性能崩壊（精度 4.52%）の要因
この極めて低いスコアは、モデルの知識不足ではなく、**「回答出力フォーマットの不一致による評価スクリプトでの文字列マッチングの失敗」**が主な要因です。

*   **要因の特定**:
    `run_eval_telecom.sh` 内の判定ロジックでは、モデルの生成テキスト内に `"option X"` （正解のオプションラベル）が含まれているかを `correct_option.lower() in pred.lower()` という判定式でチェックしています。
    *   **BaseModel**: 指示に従い `"option 2\nExplanation:..."` のように `"option 2"` という文字列を含めて回答していたため正しくマッチしていました。
    *   **model1_math**: 数学データセット（`MathInstruct`）を用いたFTの影響で、出力を簡潔にする傾向や独自の推論回答スタイルが学習されたため、指定の文言を無視して単に `"2\nExplanation:..."` のように数字の `2` や解説のみを出力するようになってしまいました。
    *   **結果**: モデル自体は正しい選択肢の番号を選択できているにもかかわらず、文頭に `"option "` というプレフィックスがないため、判定式ではすべて「不正解」としてカウントされてしまいました。

### ② model2_coding (Coding FT) の興味深い挙動
*   **MBPPスコアの低下**: Coding FTを行ったモデルですが、MBPP (pass@1) が BaseModel (0.582) から `0.536` へと低下しています。一般的なプログラミングのコード生成能力そのものは、少量のSFTデータ（`codealpaca`）によるアライメントの崩れなどでわずかに劣化した可能性があります。
*   **TeleQnAで最高精度（57.61%）を記録**: 一方で、多肢選択式の論理的問答である TeleQnA においては、Medicine FTモデルをも上回る最高精度（57.61%）を記録しました。
    *   **考察**: コードデータセットによる学習は、LLMの「論理的推論力」や「プロンプトへの追従能力」を大幅に強化することが広く知られています（Code-SFTの効果）。TeleQnAは高度な専門ドメインの選択式問題であり、設問内の複雑な文脈を整理して論理的に回答を選択する必要があるため、Coding FTによってモデルの推論能力が底上げされ、結果的に最も高いスコアを記録したものと考えられます。

### ③ model3_medicine (Medicine FT) の評価
*   `medqa` データセットでファインチューニングされた `model3_medicine` は、TeleQnA の Final accuracy が `0.5292` となり、BaseModel (0.5037) から着実に改善しています。
*   また、一般的な言語タスクや医学ドメインである `pubmedqa` でも `0.7660` と最も高いスコアを出しており、医療分野の知識獲得に成功していると言えます。

## 5. 関連（In-domain）と非関連（Out-of-domain）の観点による評価分析

今回の評価では、各モデルが**「学習（FT）時に用いたデータ（またはその類似領域 = In-domain）」**と**「学習（FT）時に用いていないデータ（= Out-of-domain）」**の両方でベンチマークテストを行っています。

専門ドメインでFTを行うと、他の領域のスコアが低下する「破滅的忘却 (Catastrophic Forgetting)」や、逆に論理的思考力が他の専門領域に好影響を与える「汎用的な波及効果」などの興味深い挙動が観察できます。

### 🔄 各モデルの評価比較分析

#### ① model1_math (Math FT)
*   **学習に用いたデータ (In-domain)**: `gsm8k`, `minerva_math`
    *   **結果**: いずれも低下（例: `gsm8k` 0.7642 → `0.6482`）。
    *   **考察**: 通常はIn-domainで性能向上するはずですが、今回は悪化しており、FT時のハイパーパラメータ（学習率2.0e-5やエポック数3.0）が過剰であったか、アライメントの崩れが発生したと判断できます。
*   **学習に用いていないデータ (Out-of-domain)**: 一般言語 (GLUE), `mbpp`, `TeleQnA`
    *   **結果**: 一般言語の `mnli` (0.5579 → `0.3922`) で急激に性能が低下しており、数学FTの代償として一般言語理解で強い破滅的忘却が発生しています。

#### ② model2_coding (Coding FT)
*   **学習に用いたデータ (In-domain)**: `mbpp` (コード生成)
    *   **結果**: 0.582 → `0.536` (微減)。
    *   **考察**: コードの直接的な生成精度そのものはベースラインを超えられませんでしたが、破滅的な低下は免れています。
*   **学習に用いていないデータ (Out-of-domain)**: 一般言語 (GLUE), `TeleQnA`, 数学
    *   **結果**: 驚くべきことに、未学習の通信ドメイン知識問題である `TeleQnA` (0.5037 → **0.5761**) や、一般言語の論理的推論である `mnli` (0.5579 → **0.5806**) でスコアが大きく向上しました。
    *   **考察**: Codingの学習データ（Code-SFT）が、モデルに「論理的に選択肢を絞り込み、命令に従って正解を導き出す」汎用的な推論能力を授けたことを示しています。別のドメインであっても、論理的な思考を要求されるタスクにおいて強力な波及効果をもたらしました。

#### ③ model3_medicine (Medicine FT)
*   **学習に用いたデータ (In-domain)**: `pubmedqa` (医療論文), `medqa`
    *   **結果**: `pubmedqa` が 0.7460 → **0.7660** に向上。
    *   **考察**: 最も模範的なFTであり、狙い通りの医療領域で正しく学習効果が出ています。
*   **学習に用いていないデータ (Out-of-domain)**: 一般言語 (GLUE), `TeleQnA`, `mbpp`, 数学
    *   **結果**: `TeleQnA` が 0.5037 → **0.5292** に向上。数学や一般言語タスク (`mnli` 0.5579 → `0.5376`) では微減に留まり、大きな破滅的忘却を起こさずにドメイン能力を上乗せすることに成功しています。

## 6. 推奨アクション
*   **TeleQnA 評価の判定ロジックの改善**:
    現在の文字列前方一致や単純な `in` 判定は、FTモデルのプレフィックス出力の変化（例: `"option 1"` ではなく単に `"1"` とする）に非常に脆弱です。
    `pred` の中から正規表現で最初の数字を抜き出すなどのパース処理を追加することで、モデル本来の正解率（`model1_math` を含む）を正しく評価できます。
