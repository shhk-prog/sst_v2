# flmsec.tex 最終修正に向けた実装計画

## 目標
ユーザーからの詳細なフィードバック（13項目の修正優先度A〜C）に基づき、`flmsec.tex` 内の結論の表現、評価指標の定義、実験設定の詳細、および表の記述を再修正します。

## 修正内容

### Priority A: 結論・定義・表の整合性
1. **結論のトーンダウン**: 
   - 「完全アライメントと高数学力」「全安全性ベンチマークで最も安定」「他手法を圧倒」といった強すぎる主張を削除します。
   - 表現を「本設定ではSSTが最良のSafety–Utility trade-offを示した」「SSTは複数条件で有力な候補となった」「ただし優位性はドメイン・マージ強度・シードに依存した」などに変更し、PPLが数万に達する極端値や有用性の低下など、手法の限界を明示します。
2. **Validity-aware Pareto AUCの数式定義**: 
   - ユーザーから指定された数式定義のLaTeXブロックに沿って説明を書き換えます。
3. **Safety指標の名称・方向・分母の統一**:
   - `Safety Ave [Harmful Content]` や `Safety Ave [Refusal-Filtered]` などの名称を、表で指定された「Original ASR」「Conditional ASR」「Valid Response Rate」「Valid Safety Rate」「Refusal Rate」に統一し、望ましい方向と定義を明記します。
4. **$\alpha=0$ と $\alpha=1$ の定義の一般化**:
   - $\theta_m^{(h)} = \theta_u + \alpha\,\mathcal{T}_h(\Delta_{\mathrm{patch}})$ という変換式を追加し、$\alpha=0$ と $\alpha=1$ が各手法で何を意味するのかを本文中に追記します。
5. **極端なPPL等の検証追記**:
   - PPLの極端値について、トークナイザの不整合、モデル崩壊、または評価パイプラインの失敗の可能性として本文の考察で言及します。

### Priority B: 方法・再現性
6. **安全モデル学習の詳細追加**:
   - データ出典（TrustLLMの有害プロンプト等）、学習件数、train/val分割、拒否応答作成方法、LoRA詳細（rank, alpha, dropout, layer, lr, batch, optimizer, scheduler, length, steps/epochs, merge手順）などのハイパーパラメータをAppendixに追記します。
7. **Gibberish判定規則の擬似コード化**:
   - 指定されたアルゴリズムブロックを用いて、Gibberish判定の閾値（空出力長、反復比率、n-gram等）を具体的に記載します。
8. **評価件数の列分離**:
   - 前回の修正で追加した「本研究での評価件数」列について、「抽出規則（固定seedで層化、固定インデックス等）」を追加し、全件評価なのかサンプリングなのかを明白にします。
9. **コード・AlpacaEvalのパラメータ固定表記**:
   - 指定されたLaTeX記述を用いて、生成パラメータ（$n$, temperature, top-p, max_new_tokens等）およびAlpacaEval（固定100件、judgeモデル、version等）を具体値で固定表記します。

### Priority C: 文章・構成
10. **予備実験の位置づけ変更**:
    - 「DAREやTIESは危険」と断定する表現を避け、「予備実験はGibberish生成を安全性改善と誤解させ得ることを示す探索的分析である。主要結論はメイン実験に基づく。」といった位置づけに書き換えます。
11. **機序の仮説化**:
    - 「これらは〜〜によるものである」といった因果関係の断定を避け、「これらには〜〜が関与する可能性があるが、直接測定しておらず今後の課題とする」という仮説の表現に変更します。
12. **Taxonomy表の注釈追加**:
    - 表注に「本列は各手法の目的関数または統合規則に安全性情報を明示的に含める程度を相対的に整理したものであり、実験上の優劣を表すものではない。」と追記します。
13. **4フェーズの研究史表の削除**:
    - 以前の版に残っている場合は当該テーブルを削除します。
