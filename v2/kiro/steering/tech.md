# 技術方針・検証フック仕様 (SST-Merge Technical Steering) - 最終決定版

## 1. ランタイムと技術スタックの定義

SST-Merge の実験環境は、以下の技術スタックに制限されます。

- **ランタイム**: Python 3.10 以上 (Cuda 11.8 以上)
- **ディープラーニング**: PyTorch 2.0 以上
- **LLM/アダプタスタック**: Hugging Face `transformers`, `peft`, `trl`
- **マージエンジン**:
  - 提案手法（SST-Merge）: `v2/scripts/merge/sst_merge_core.py` による独自実装。
  - 比較手法: `arcee-ai/mergekit` の公式 CLI または公式 API。公式実装が無い手法については著者公開実装を直接利用。
- **評価ハーネス**: `lm-evaluation-harness` (EleutherAI 公式)

---

## 2. 開発および実験実行時の技術的制約

### 2.1 比較手法のカスタムフォールバックの排除（RuntimeError強制）
- 比較手法を実行するスクリプト内において、`mergekit` がインストールされていない等の理由で、独自に実装された `CustomBaselineMerger` などのカスタムマージロジックへ自動フォールバックすることを**厳格に禁止**します。
- インストールチェックやインポートで失敗した場合は、フォールバックせず即座に `RuntimeError` を送出してプログラムを停止させなければなりません。

### 2.2 実験管理のYAML化の強制
- 実験パラメータ（モデル、データセット、シード、$\alpha, k$ のスイープ）をスクリプト内にハードコーディングすることを禁止します。
- すべての実験は、`configs/aaai27/*.yaml` に定義された設定ファイルをパースして実行されなければなりません。

### 2.3 再現性とメタデータの記録
- **シード固定**: PyTorch, NumPy, Python Random, Hugging Face Trainer の乱数シードは必ず固定（デフォルト `42`）し、主要実験は最低 3 seed で検証します。
- **メタデータ保存**: すべての実験成果物（LoRAアダプタ、マージモデル）の保存ディレクトリには、ベースモデル名、アダプタの学習率、Epoch数、学習データセット名、マージ手法名、および Git Commit Hash / 実行コマンドを記述した `merge_metadata.json` を同梱することを義務付けます。

### 2.4 Data-Free 実験における IO およびキャッシュ遮断
- `data_free_sst` メソッドを実行するプロセスにおいては、`v2/data` ディレクトリ内のあらゆる JSON ファイルへの IO（読み込み）をフックし、検知した場合は例外を発生させて停止します。
- 過去の実験で生成された FIM キャッシュファイル、勾配統計キャッシュファイル等の「データセット由来の統計情報」を読み込むことも禁止し、完全な Data-Free 状態を維持します。

## 3. Scientific Integrity Rules（科学的厳密性・再現性ルール）

本プロジェクトでは、実験結果の信頼性・再現性・公平性を保証するため、以下のルールを厳格に適用します。

### 3.1 評価データの学習利用禁止
- 評価用ベンチマーク（HarmBench, JailbreakBench, StrongREJECT, WildJailbreak, MMLU-Pro, IFEval, GSM8K, AlpacaEval など）は、LoRA学習、FIM推定、ハイパーパラメータ（α, k）の選択、およびモデル選択に使用してはなりません。
- 評価データは最終評価専用とします。

### 3.2 実験グリッドの完全実行
- 事前に定義した α、k、seed の実験グリッドは途中で打ち切らず、すべて実行します。
- 特定条件のみを追加・削除して有利な結果のみを報告することを禁止します。

### 3.3 全結果の保存
- 最良結果のみを保存することを禁止します。
- すべての seed、すべての α、すべての k の評価結果を保存しなければなりません。
- 失敗した実験についても、原因が判別できるログを保存します。

### 3.4 メタデータの完全保存
- 全実験について `merge_metadata.json` を保存します。
- メタデータには少なくとも以下を含めます。
  - Base model
  - Merge method
  - Dataset
  - Random seed
  - Hyperparameters
  - Git commit hash
  - Execution command
  - Timestamp

### 3.5 図表の再生成可能性
- 論文中のすべての図表は `results/raw/` に保存された生データから再生成可能でなければなりません。
- 図のみを手作業で修正・保存することを禁止します。

### 3.6 比較手法の公平性
- ベースラインは必ず公式実装（official implementation）または著者公開実装を使用します。
- 独自実装による比較結果を論文中のベースラインとして報告してはなりません。

## 4. 自動検証フック（Steering Hook）の要件

実験開始時の自動検証フック (`steering_hook.py`) は、以下の検証を行い、ルール違反を検出した場合は即座に例外（`ValueError` / `RuntimeError`）を送出してプロセスを強制終了します。

1. **ベースモデル制限の検証**:
   - 入力のモデルパス/IDに `Meta-Llama-3.1-8B-Instruct` (またはクロス検証用の Mistral, Qwen) が指定されているかチェックします。
2. **比較手法の公式実装強制**:
   - `ties`, `dare`, `task_arithmetic` が指定された際に、`implementation` が `mergekit` で実行されているかを検証。
3. **Data-Free 時のデータ・キャッシュ統計遮断**:
   - `data_free_sst` が指定された場合、引数内のデータセットパス、統計キャッシュパスがすべて `None` または空であることをチェック。
   - `builtins.open` をフックして、実データへのアクセスを動的に遮断。
4. **データセット重複の禁止検証**:
   - FIM推定に用いるデータセットと、評価（lm-evalやHarmBenchなど）に用いるデータセットが重複していないか（物理パスの一致検証）をチェック。
   - 学習に用いるデータセットと、評価用のデータセットが重複していないかをチェック。
